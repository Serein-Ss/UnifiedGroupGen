# 重构后功能一致性核验

核验日期：2026-10-31。基准是用户下载的服务器原始源码 `../tmp/UnifiedGroupGen(3).zip`，不是只与上一轮配置重构备份比较。原始代码以独立包名加载，当前模型/训练/生成/评价生产代码未修改，也未恢复任何正式任务。

结论：**现有模型、核心数学计算及生成/指标计算保持兼容；Lightning新训练流程与原训练器并非严格同一训练轨迹。** 因而，“目录重构没有换掉模型”成立，“重新训练一定得到原来的权重与最优轮次”不能确认。

## 已实际核验的内容

| 对象 | 本轮验证 | 结果 |
|---|---|---|
| 已有模型和历史文件 | 150个受保护文件的哈希，包括15套模型的30份最优/最后权重 | 全部未变 |
| 网络与检查点接口 | 15套最优权重分别在服务器原版和当前版严格加载 | 全部通过 |
| 实验定义 | 15套分组配置展开后与原服务器完整配置比较 | 全部相等 |
| 描述Transformer与OrbitFlow前向 | 20组真实测试记录输入，包含联合模型的两个来源 | 描述损失、连续速度逐位相等 |
| 训练损失和梯度 | 6种已训练模型、8个真实记录批次，同权重、同随机数、FP32 | 各项损失相等，1264个梯度张量哈希相等 |
| 自由群与轨道选择 | 三个基础模型与联合多性质模型，共6组自由描述采样 | 描述相同；未指定组成、群或轨道，保留kind与现有来源上下文 |
| 连续结构生成 | 上述代表模型6组固定描述、64步采样 | 独立状态、晶格、坐标最大差异为0，CIF文本相同 |
| CSP与DNG指标 | 3D/2D各两类，共4组；含失败结构分母与Match@1/5/20 | 科学指标汇总相等 |
| 指纹与覆盖率 | NaCl三维与MoS₂二维两例；61维结构与132维组成指纹 | 数组及覆盖率结果相等 |
| 性质评价 | 包含成功、超差与预测失败的输入 | 计算结果相等 |
| 指标函数 | 23个函数与原服务器源码比较 | 仅归一化常数资源路径迁移，计算内容相同 |

指纹标准化JSON的字节格式变化，但解析后的所有内容相等；上述指纹数组也实测相同。这里不把JSON格式差异误认为指标公式变化。

这些是软件与数值一致性检查，不是重新生成完整15套研究指标。实际材料的结构合理性、重建率、分布质量仍以对应正式评估为准。自由描述与固定描述连续采样是分开验证的，本轮没有重新运行每套模型的大批从头生成。

## 已确认的训练流程差别

### 1. 批次随机数不同

原训练器用全局Python随机状态组织批次；该状态还被每个批次的训练目标构造消耗，即使组成与观测条件概率为0，仍保留每条记录两次随机抽取。

当前Lightning数据加载器用独立的 `random.Random(seed + epoch)` 组织批次。40条真实记录副本的检查中，第一轮批次相同，第二轮不同。因此，相同seed并不能让新旧训练器经历完全相同的优化步骤；本轮没有修改这一行为。

### 2. BF16训练下的验证精度不同

服务器原训练器只在训练步骤启用autocast，验证在FP32下计算。当前Lightning的`bf16-mixed`也用于验证。

本机RTX3060上，同一个MP-20已训练模型、同一条`mp-10009`记录、同一随机数下：

| 验证分量 | 原FP32策略 | 当前BF16 mixed策略 |
|---|---:|---:|
| 描述损失 | 2.69284534 | 2.69008374 |
| 连续流损失（坐标/9） | 13.56650162 | 13.54322433 |
| 晶格损失 | 0.14510661 | 0.15391141 |
| 原始坐标损失 | 120.79255676 | 120.50381470 |

这是精度策略的配对测量，不能用来判断新模型生成质量更好或更差。验证数值不同，可能影响学习率下降、早停与最优检查点选择。

### 3. 历史断点与原生Lightning断点不同

旧`.pt`可以用于推理、指标评价及`initialize_from`加载权重；当前`resume`只接受原生Lightning格式的`.ckpt`。`initialize_from`会开始新实验，不能当作完整恢复旧优化器、调度器和原训练进度。

当前原生Lightning内部的恢复已有连续训练/中断续训一致性测试，但它不等于“旧手写训练器的`.pt`可以无损转换成新训练轨迹”。

## 对当前工作的影响

1. 已有15套模型无需因为此次目录和配置重排而作废，既有权重没有被重训练或替换。
2. 使用这些权重进行生成及指标计算，受检功能与原版兼容；新的入口、配置路径、原生断点和性质评价启用方式应按当前说明使用。
3. 若要严格复现原15套模型的训练方案，需要先对齐批次RNG与验证精度，再做跨训练器多轮配对；否则应把当前Lightning训练方案作为明确记录的新训练协议。
4. 本轮没有完整重训、没有完整性能复测，也没有跨Linux/Windows、PyTorch/CUDA版本的逐位一致性证明。

此前配置/接口回归测试通过，只能证明其覆盖的配置、单步运算与入口行为正确，不能扩大解释为完整训练轨迹相同。
